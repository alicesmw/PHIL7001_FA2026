Before we start · Colab basics 1/5

Google Colab: Python in your web browser

  • Google Colab (short for “Colaboratory”) is a free website where you write and run Python inside your browser — nothing to install.
  • You work in a notebook: one document that mixes code, the results of that code, and your own notes. Colab notebooks are Jupyter notebooks (files ending in .ipynb), the standard format in data science.
  • Your code does not run on your laptop. It runs on a Google computer in the cloud, called the runtime (you will also hear “session” or “kernel”). The Connect button at the top right links your notebook to one — it also connects automatically the first time you run code.
  • Notebooks save automatically to your Google Drive, in a folder called Colab Notebooks — just like a Google Doc.

Open your first notebook

  1. Go to colab.google
  2. Sign in with a Google account
  3. Click New Notebook (or, inside Colab: File → New notebook)
  4. Rename it: click the title Untitled0.ipynb at the top left

Before we start · Colab basics 2/5

Anatomy of a notebook: cells

  • A notebook is a column of boxes called cells. There are two kinds:
    • Code cell: holds Python code, with a ▶ button on its left. Its output (the result) appears directly underneath.
    • Text cell: holds headings and notes for humans. Text cells are never run as code.
  • Add cells with the + Code and + Text buttons at the top of the notebook (or hover between two cells).
  • Inside a code cell, a line starting with # is a comment: a note for humans that Python skips.
  • Click a cell to select it; its small toolbar (top right of the cell) lets you move it up/down or delete it.

What a notebook looks like

My first notebook text cell
▶
# my first line of Python
print("Hello, world!")
Hello, world!

↑ a code cell (selected) and, under it, its output

Before we start · Colab basics 3/5

What does it mean to “run” a cell?

  • Running (or executing) a cell means asking the computer to carry out its instructions — line by line, top to bottom — and show any result.
  • To run the selected cell: click its ▶, or press Ctrl+Enter (⌘+Enter on a Mac). Shift+Enter runs it and moves to the next cell.
  • While it runs, the ▶ spins (click it to stop). When it finishes, a number appears in brackets — [1], [2]… — the execution count: the order in which cells were run. [ ] means “not run yet”.
  • Output = whatever you print(), plus the value of the cell’s last line.
  • An error stops the cell and shows red text (a “traceback”). Read its last line first: it names the problem. Errors are normal — fix the code and run it again.

After running two cells

[1]
x = 5
print(x + 2)
7
[2]
print(y)
NameError: name 'y' is not defined
[ ]
y = 10   # not run yet

Python only knows about y once a cell that creates it has actually been run.

Before we start · Colab basics 4/5

Running cells out of order — and why it matters

  • Colab lets you run cells in any order, and re-run them as often as you like. Where a cell sits on the page does not matter.
  • What matters is the order you actually ran them: the runtime keeps a memory (its “state”) of every variable created so far — even by cells you have since edited or deleted.
  • Consequences:
    • The page can mislead you: the code you see may not match what is in memory.
    • Hidden dependencies: a cell may only work because of something run earlier (or in a deleted cell). Run top to bottom tomorrow — or by a classmate — it may give different results or a NameError.
    • Re-running a cell like x = x + 1 changes x every time.
  • Tip: the execution counts tell you the true order. If they jump around, be suspicious.

Cells run in the order 1 → 2 → 3

[1]
x = 5
[3]
print(x)
100
[2]
x = 100

Reading top to bottom you would expect 5, but the bottom cell ran second, so x was already 100 when print(x) ran.

Before we start · Colab basics 5/5

Restart, run all, save: good habits

  • Runtime → Restart session (older versions: “Restart runtime”) wipes the runtime’s memory. All variables are forgotten, but your code and notes stay.
  • Runtime → Run all runs every cell from top to bottom; Run before runs everything above the selected cell.
  • Colab disconnects if you are idle for a while, and free sessions last at most 12 hours. When that happens, memory is wiped — just run your cells again from the top.
  • Files uploaded into the Files panel (folder icon, left) are temporary: they vanish when the runtime is shut down. Keep data in Google Drive and connect it with drive.mount(...), as in today’s activity.
  • Opened someone else’s notebook (e.g., a course link)? Use File → Save a copy in Drive so your changes are kept in your own copy.

Habit to build

Before you share or submit a notebook: Runtime → Restart session and run all. If it runs top to bottom with no errors, anyone can reproduce your results — not just the version of you who ran cells in a lucky order.

1. Variables, Assignment, and Basic Data Types

  • Variables store data/values that we can use and manipulate in our programs.
  • Variables can be named anything you (the programmer) wants
  • Variable names in python are case sensitive, cannot start with a number, and must contain only alpha-numeric characters and underscores (e.g., “3thirty” is not allowed, “thirty3” or “thirty_3” is ok)
  • Think of a variable name like the address label of a building, or the name of a (sometimes mysterious) ingredient
  • Data type describes the the type of the data/value located at the address
  • In Python, you don’t have to explicitly specify the data type when you create a variable (not true in some other programming langauges)
  • You can create your own data type, but Python already has a few built-in categories of data types that we will use
  • The ones we will use most commonly are: Text (e.g., “hi”), numbers (e.g., 5, 92.43 ), Boolean values (e.g. True, False)
  • For full types of supported data types in Python: https://www.w3schools.com/python/python_datatypes.asp

Creating variables

  • use = to assign value
  • may sometimes see +=, -=, *=, /=
  • x+=1 is the same as x=x+1
  • a-=b is the same as a=a-b
  • == is different (for comparing the values of variables)

Importing data

Importing external libraries and functions overview

  • NumPy, Pandas, Matplotlib, Seaborn, Statsmodels etc. are commonly used open-source Python libraries developed by other people
  • Using existing functions in existing libraries helps simplify your own workload (no need to reinvent the wheel everytime)
  • But you need to make sure you understand the functions you import and use
  • You’ve already seen functions from the library statsmodels (e.g., ols())
  • seaborn (e.g., regplot())
  • You can import entire libraries or just individual functions from libraries
  • Aliasing means using a shorter more convenient name for a library
  • Because you need to specify what library a function is in everytime you use it if you import the entire library

Examples you’ve seen before

Code

# Importing libraries
import statsmodels.formula.api as smf
  • statsmodels is the main library.
  • .formula and .api are submodules within statsmodels
  • submodules are just smaller subsections nested within the larger library (the difference is mostly conceptual)
  • similar to when you borrow a book from the library, you might see a call number on the spine (e.g. using the Library of Congress classification system, BD450 .C5356 2011)
  • Class B for philosophy, psychology, religion.
  • Subclass BD for speculative philosophy
  • BD300-450 for Ontology, including being, the soul, life, death etc. https://www.loc.gov/aba/cataloging/classification/lcco/lcco_b.pdf
  • “as” specifies an alias (or shorthand)

Code

# Importing libraries
import pandas as pd
  • pandas is the full name of the library
  • typical alias for pandas is “pd”
  • Without alias: pandas.read_csv(“file/path”)
  • With alias: pd.read_csv(“file/path”)

Code

# Importing libraries
from pandas import read_csv
  • If you only need 1 or 2 functions, you might see people only importing that specific function to save time on typing
  • read_csv(“file/path”)
  • no need to add “pd.”, can just use read_csv() directly
  • But functions can be arbitrarily named anything, so some people may coincidentally use the same name for functions that do different things
  • That’s why we don’t usually import a function from a library directly, in case there are clashing names
  • e.g., if I had created a custom function called .min(), but pd.min() already exists, I can still use both if I call mine alice.min() and pd.min()

Control flow Loops and Conditionals

  • Control flow allows your programs to make decisions and repeat actions.
  • If statements: if(condition)
  • If, else statements: if(condition): else (other_condition)
  • For loops

Code

# If-else statements
temperature = 22.5

if temperature > 29:
    print("It's hot outside!")
elif temperature > 20:
    print("Nice weather!")
else:
    print("It's cool outside.")

# For loops
scores = [85, 92, 78, 95, 88]
total = 0

for score in scores:
    total = total + score

average = total / len(scores)
print(f"Average score: {average:.1f}")

#also works
total = 0
for i in scores:
    total = total + i

average = total / len(scores)
print(f"Average score: {average:.1f}")
